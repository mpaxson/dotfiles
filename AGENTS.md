# AGENTS.md

Personal dotfiles, managed with GNU Stow. Everything here is symlinked into `$HOME`.

## Setup

```bash
stow .        # from the repo root; target is the parent dir, i.e. $HOME
stow -R .     # restow after adding or moving files
```

`.stow-local-ignore` controls what stays behind. Entries with a leading `/` are
anchored to the repo root; bare names match at every level, so a bare `scripts`
would also hide `scripts/` directories nested inside skills.

## Skills are single-sourced in `.claude/`

`.claude/skills/`, `.claude/agents/` and `.claude/commands/` are the source of
truth. Everything else is generated by
[`agent-harness`](.claude/skills/agent-harness/SKILL.md):

| Path | Kind |
| --- | --- |
| `.agents/skills` → `../.claude/skills` | symlink |
| `.codex/skills/` | generated adapters for agents and commands |
| `.openhands/microagents/` | generated |

Regenerate after touching anything under `.claude/`, and check in CI:

```bash
uv run .claude/skills/agent-harness/scripts/sync_harnesses.py
uv run .claude/skills/agent-harness/scripts/sync_harnesses.py --check
```

Never hand-edit a generated file — the next sync overwrites it.

## Two rules the sync enforces, because strict clients fail silently on both

A skill whose frontmatter `name` does not match its directory, and a skill whose
frontmatter does not parse as YAML, are **skipped without an error** by Codex and
other spec-compliant clients. The skill just disappears. The sync script hard-errors
on both instead, so a failed sync is the signal.

The usual YAML trap is a `description:` containing `": "` — a plain YAML scalar
cannot hold colon-space. Quote the whole value:

```yaml
description: 'Manage MCP servers: discover and execute tools.'
```

## `.claude/skills/gstack` is a gitlink with no `.gitmodules`

Git records it at mode 160000 but there is no submodule mapping, so a fresh clone
gets an **empty directory**. 55 skills are absolute symlinks into it
(`/home/kettle/dotfiles/.claude/skills/gstack/...`) and therefore resolve only on
the machine this repo lives at that exact path. Upstream is
<https://github.com/garrytan/gstack>.
